## Question

What exactly goes in the archived year file, and how is it versioned?

## Sub-questions

- **Tables.** `esl_cohorts`, `esl_classes`, `esl_students` for the year. Are teacher `users` rows included by id, by name, or both? A file naming real teachers is worth more in an accreditation request than one naming opaque ids — but `users` is the shared CAS table, so copying user rows into an ESL archive duplicates live data.
- **Derived fields.** ESL derives `code` and `label` on read (`cohortCode`, `cohortLabel` in `src/convex/shared/esl.ts`) and `chineseClass` is reconstructed on read from grade. Should the file store the derived values, so a reader in five years does not need this codebase to interpret it?
- **Identity across years.** A student appearing in several archived years: is `schoolStudentId` enough to stitch them, or does the file need to preserve something else?
- **Versioning.** ADR-0013 already establishes `SNAPSHOT_VERSION` for CAS backups. Does the ESL archive reuse that version, get its own, and what is the policy when the ESL schema changes — flag-and-keep (ADR-0013's existing answer) or something else?
- **Format.** JSON matches the existing Drive payload and needs no dependency. Is JSON right, or does the archive want to be a spreadsheet the office can actually open without us?

## Why this matters

The file is the artifact. After the rows leave Convex, this shape _is_ the record — there is no second source to check it against.

Blocked by #143 (what leaves Convex) — the file must cover every deleted row, or the year is unrecoverable.
