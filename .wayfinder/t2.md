## Resolution

Findings are in the comment on this ticket. Branch: `research/esl-archive-drive-auth` at `c5d204a` (`.wayfinder/t2-findings.md`).

Three findings, one of which redirects the map.

**1. The Drive path is dead on prod, not just locally.** #133 already investigated this and observed `invalid_grant` from `scheduledBackup` — the shared refresh token is expired. ADR-0012's "not functioning" is live, not stale. Worse, #133 finds local and dev hold _identical_ credentials and the same `GOOGLE_DRIVE_FOLDER_ID` as prod, with `daily-drive-backup` registered unconditionally on every deployment.

**2. Sharing one folder is free.** `GOOGLE_DRIVE_FOLDER_ID` is read once (`driveBackup.ts:41`), so both the HWIS backup and the ESL archive would use it. No second folder id needed. (Unset locally — uploads would land in the service account root.)

**3. This map is blocked by #133.** Writing an ESL archive before Drive separation risks a dev archive landing in the production folder.

**Also found:** a failed upload writes nothing to Convex — it is a thrown error inside an `internalAction`, invisible from the app. And the Drive scope choice (`drive.file` sees only app-created files; `drive` sees the shared folder) is a genuine fork, deferred to #147.
